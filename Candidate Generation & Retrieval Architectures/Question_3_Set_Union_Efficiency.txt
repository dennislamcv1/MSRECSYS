A Python set is a hash table, so adding an item or checking whether it is already present takes constant time on average; building the three sets and merging them with | therefore costs roughly O(n) for n total candidates, with every duplicate collapsed by a single hash lookup. Combining the lists and finding unique items by iteration instead means checking each element against the items already kept, which is a linear scan of a list and grows to O(n²) comparisons as the candidate pool grows. The union is also executed in optimized C inside CPython, so it avoids the per-item overhead of an interpreted Python loop on top of having the better complexity.
